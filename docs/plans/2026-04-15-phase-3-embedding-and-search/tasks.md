# Execution Plan: Phase 3 — Embedding + Search

## Overview

Implementing the `Embedder` (fastembed wrapper), `Searcher` (orchestration), `SearchResult` dataclass, full-vault `index_vault()`, and incremental `update_files()` per [design.md](design.md) and PLAN.md steps 19-22.

**Design Approach**: thin-adapter-plus-orchestrator (`Embedder` isolates fastembed, `Searcher` composes config+chunker+store+embedder).

**Target State** (from design.md success criteria):
- `Searcher(vault_root).index_vault()` runs scan → chunk → embed → store end-to-end on the real vault.
- `update_files(paths)` re-embeds named files in <2 s (warm cache).
- Fast TDD loop stays <2 s and never downloads a model.
- Phase 1 + Phase 2 modules unchanged.

## Implementation Strategy

### Phase rationale

The work is one strictly sequential chain by TDD necessity — each step composes the previous step's output:

```
setup(fastembed dep)
   ↓
Embedder (step 19)
   ↓
SearchResult + Searcher.search (step 20)   ← uses Embedder via injection; tests use FakeEmbedder
   ↓
Searcher.index_vault (step 21)             ← uses Searcher class shell + Store.bulk_insert
   ↓
Searcher.update_files (step 22)            ← reuses index_vault helpers + Store.upsert_file
   ↓
Hardening (lint, full test run, e2e demo)
```

There is no useful parallelism: each beads issue is a logical commit and each commit depends on the prior to be green. This matches Phase 2's grain (one issue ≈ one commit).

### Testing strategy

- One `@pytest.mark.slow` test exercises real `fastembed` (downloads model on first run). It is the only slow test.
- All `Searcher` tests use an inline `FakeEmbedder` class injected through the constructor. No `Mock`, no `monkeypatch`, no `Protocol` (matches the codebase's "real implementations + fake data" precedent — research §"Existing test conventions").
- Fast-vector convention from Phase 2 holds: `[0.1] * 384`, directional vectors like `[1.0] + [0.0] * 383` for ordering tests.
- `tmp_path` for every persistent test; `Store` fixture in `conftest.py` already exists.
- Test naming: `test_<subject>_<behavior>` (e.g., `test_index_vault_skips_files_with_index_false_override`).
- Error assertion: `with pytest.raises(ValueError, match="..."):` — same form as `test_store.py:171,178`.

        self,
        vault_root: Path,

## Phase 4 — Step 21: Searcher.index_vault

**Beads**: `km-a0b` (depends on km-1l2)

### Objective
Implement the full-rebuild pipeline as `Searcher.index_vault()`. Must apply `index = false` filtering by walking `VaultConfig.overrides` directly (per design — neither `resolve_for_file` nor `chunker` know about indexing).

### Prerequisites
- [ ] km-1l2 closed (Searcher class exists).

### Changes Required

#### Add to `src/km/search.py`

```python
class Searcher:
    ...
    def index_vault(self) -> dict[str, int]:
        """Full re-index. Returns {'files': N, 'chunks': M}."""
```

**Implementation notes (HOW)**:
1. `config = load_config(self._vault_root)`.
2. `paths = scan_vault(self._vault_root, config.scan)` — absolute paths.
3. Build `(chunk, text_to_embed)` pairs:
   ```python
   items_to_embed: list[tuple[Chunk, str]] = []
   for absolute in paths:
       relative = str(absolute.relative_to(self._vault_root))
       if not _should_index(config, relative):
           continue
       file_chunk_config = resolve_for_file(config, relative)
       try:
           text = absolute.read_text(encoding="utf-8")
       except UnicodeDecodeError:
           continue   # skip binary-ish files; matches Phase 2 e2e demo behavior
       for chunk in chunk_markdown(text, relative, file_chunk_config):
           items_to_embed.append((chunk, chunk.content))
   ```
4. Bulk embed once: `vectors = self._embedder.embed([t for _, t in items_to_embed])`.
5. Zip into Store-shaped items: `items = [(chunk, vec) for (chunk, _), vec in zip(items_to_embed, vectors, strict=True)]`.
6. `self._store.clear(); self._store.bulk_insert(items)`.
7. Return `{"files": <count of distinct file_paths in items>, "chunks": len(items)}`. (Or compute via `self._store.stats()` after insert — same result.)

**Module-level helper** in `search.py`:

```python
def _should_index(config: VaultConfig, relative_path: str) -> bool:
    """Return False if any override matching this path sets index=False."""
    for override in config.overrides:
        files = override.get("files", "")
        patterns = [files] if isinstance(files, str) else list(files)
        for pattern in patterns:
            if PurePosixPath(relative_path).match(pattern):
                if override.get("index") is False:
                    return False
                return True   # first-match wins, same semantics as resolve_for_file
    return True
```

**Pattern reference**: `resolve_for_file` at `config.py:66-86` uses the same first-match-wins glob model. We cannot reuse it directly because it strips `"index"` (`config.py:78`) — we are the consumer that needs that key.

4. **`test_should_index_helper_first_match_wins`** — fast. Direct unit test on `_should_index` with crafted `VaultConfig` to lock in semantics (not strictly required if 2 covers it, but pins the helper).

**Beads**: `km-6qy` (depends on km-a0b)

### Objective

### Prerequisites

### Changes Required

#### Add to `src/km/search.py`

```python
class Searcher:
    ...
    def update_files(self, paths: list[str]) -> dict[str, int]:
        """Re-index the named files (or delete chunks for missing ones)."""
```

**Implementation notes (HOW)**:
1. `config = load_config(self._vault_root)`.
2. Stats accumulator: `files_processed = 0; chunks_inserted = 0`.
3. For each `relative` in `paths`:
   - If `not _should_index(config, relative)`: continue (do not delete; the user said don't index it, deletion would surprise them).

4. Return `{"files": files_processed, "chunks": chunks_inserted}`.

- `PurePosixPath.match("Inbox/**")` on Python 3.13 only matches direct children, not recursively. `_should_index` test adapted to use `Inbox/*` patterns instead.
- `index_vault` uses per-file `embed()` calls (via shared `_chunk_and_embed_file` helper) rather than one bulk call. Acceptable: fastembed handles batching internally, and the helper is shared with `update_files`.
- Embedder exposes `lazy_load` parameter (default `False`) to enable test injection of `FakeModel` without downloading.
- Real vault e2e: 599 files, 4,739 chunks, 119s initial index (CPU), 3ms search, 2.16s for 7-file incremental update.

### Design decisions reference
- `index = false` filtering lives in `Searcher`, not in `config.resolve_for_file`.
- Embedder injection via constructor arg + duck-typed `FakeEmbedder` in tests (no `Mock`, no `Protocol`).
- One bulk `embed()` call per `index_vault` (not per-file).
- Cache directory defaults to `vault_root / .km / models/`.
- sqlite-vec L2 distance is correct without schema changes (BGE outputs are unit-normalized).
- For BGE v1.5, `embed([query])[0]` is identical to `query_embed(query)` — use `embed` for symmetry.
